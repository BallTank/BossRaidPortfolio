## 기술적 고려
### 무엇을 발견했는가
* `BossController.CaptureAuthoritativeState(...)`는 이미 HP를 authoritative DTO에 담고 있었지만, `MultiplayerBossAuthorityBridge`는 transform/animation apply까지만 담당하고 HUD는 쓰지 않았다.
* `PlayerController.InitializeCombatHUD()`는 multiplayer에서도 boss `Health` source를 그대로 `CombatHUDController`에 넘기고 있었다.
* client local boss logic/physics disable 이후에는 local boss `Health` polling/event path가 boss HP HUD truth로 남아 있으면 안 됐다.

### 무엇을 수정했는가
* multiplayer HUD bootstrap에서 player/boss `Health` source를 모두 manual mode로 전환했다.
* `MultiplayerBossAuthorityBridge`에 `CombatHUDController` resolve + boss HP normalized write + duplicate write guard + reset path를 추가했다.
* Host는 boss state capture 직후 local HUD를 갱신하고, Client는 latest received boss state apply 시점에 같은 HUD API를 호출하게 맞췄다.

### 왜 그렇게 판단했는가
* boss HP sync 문제는 damage validation 문제가 아니라 HUD source mismatch 문제였기 때문에, `Health` replication을 새로 만들기보다 existing boss authority snapshot을 HUD까지 연결하는 편이 scope가 작고 안전했다.
* Host와 Client가 서로 다른 boss HUD source를 쓰면 later regression 추적이 어려워지므로, multiplayer에서는 `MultiplayerBossAuthorityBridge` 하나로 boss HUD write 책임을 모으는 쪽이 더 단순하다.
* `CombatHUDController` 자체를 multiplayer-specialized class로 쪼개지 않고 기존 setter API(`SetBossHpNormalized`)를 재사용하면 solo path를 건드리지 않고 fix 범위를 최소화할 수 있었다.

## Topic 6. multiplayer retry count latch fix

### 오늘 반영한 작업
* `Assets/Scripts/Common/GameManager.cs`에 multiplayer defeat retry count latch state를 추가해, defeat UI가 live avatar recount가 잠깐 비어도 이전 valid count를 유지하게 바꿨다.
* same `GameManager`에서 retry count를 monotonic하게 읽도록 보강해 `0/2 -> 1/2 -> 2/2`는 허용하되, same defeat round 안에서 `1/2 -> 0/2`처럼 뒤로 내려가지 않게 정리했다.
* Host는 `2/2` consensus를 확인하면 short restart delay 뒤에만 gameplay restart를 시작하게 바꿔, panel이 `2/2`를 잠깐 보여줄 시간을 확보했다.

### 기술적 고려
#### 무엇을 발견했는가
* retry panel count는 `GameManager`가 active avatar list를 다시 세는 방식이라, restart 직전 old avatar despawn과 count refresh가 겹치면 `1/2 -> 0/2`처럼 보일 수 있었다.
* second `Enter` 입력은 실제로 `2/2` 합의가 되었어도, panel text가 same frame teardown 영향을 먼저 받으면 wrong fallback text를 잠깐 보여줄 수 있었다.
* restart decision과 retry text display가 모두 same live runtime object set에 묶여 있으면 teardown 순간의 transient state를 그대로 UI가 보게 된다.

#### 무엇을 수정했는가
* `GameManager`에 stable retry count, retry consensus flag, consensus time을 추가했다.
* valid retry count를 읽으면 highest value를 latch하고, once `2/2`가 되면 same defeat round 안에서는 count를 다시 낮추지 않게 했다.
* Host restart gate는 latched consensus 뒤 short delay를 기다리도록 바꿨다.

#### 왜 그렇게 판단했는가
* current bug는 authority truth 부재보다 teardown timing과 UI refresh ordering 문제에 더 가깝기 때문에, `GameManager`에서 count를 latch하는 편이 수정 범위가 가장 작다.
* monotonic retry count는 user-facing UX 요구사항과도 맞고, transient avatar registry empty frame을 그대로 노출하지 않게 해 준다.
* `2/2` 뒤 short delay를 두면 both peers가 final text를 볼 chance가 생기고, restart 직전 `0/2` flash도 줄일 수 있다.
