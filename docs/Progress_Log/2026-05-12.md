## Topic 1. Audio runtime baseline과 gameplay 사운드 연결

### 오늘 반영한 작업
* 사용자가 별도로 체크해 둔 4개 수정 외에, `SoundController`, `SoundLibrary`, `Assets/Resources/SoundLibrary.asset` 기반 공용 오디오 런타임을 추가했다.
* `TitleSceneController`가 `GlobalSoundController`를 bootstrap하고 `SoundLibrary`를 lazy load하도록 연결했다.
* 로비 BGM, 전투 BGM, 승리/패배 결과 BGM, 타이틀/멀티 타이틀 버튼 press SFX를 공통 경로에 연결했다.
* player attack/dash/hit/katana hit/footstep과 boss attack1/2/3, scream, death, AoE flight/fireball/breath SFX를 각 gameplay path에 연결했다.
* `MultiplayerBossAuthorityBridge`가 remote display-only boss replay에서도 AoE/fireball/fly/scream 계열 SFX를 같이 재생하도록 보강했다.

* Easy flow: `TitleSceneController -> GlobalSoundController bootstrap -> SoundLibrary load -> gameplay/title/runtime call sites -> BGM/SFX dispatch`.

### 기술적 고려
#### 무엇을 발견했는가
* 기존 브랜치에는 사운드 asset과 call site가 함께 들어와 있었지만, title/gameplay/result를 관통하는 single runtime audio entry point는 없었다.
* boss AoE/multiplayer replay는 visual replay path와 audio path가 분리돼 있어, client 화면에서 효과음이 빠지거나 부분적으로만 들리는 상태였다.

#### 무엇을 수정했는가
* singleton 기반 `SoundController`와 `SoundLibrary`를 추가하고, title runtime bootstrap과 gameplay/result call site를 연결했다.
* player local presentation path와 boss authoritative replay path에 필요한 SFX/BGM 호출을 배치했다.

#### 왜 그렇게 판단했는가
* one shared audio runtime을 먼저 두면 title/gameplay/result와 solo/multiplayer 경로가 같은 dispatch contract를 재사용할 수 있다.
* local-only player sound gate와 remote boss replay sound gate를 나누면, 중복 재생과 무음 replay를 각각 작은 범위에서 제어할 수 있다.
