## 기술적 고려
### 무엇을 발견했는가
* Host는 remote client locomotion truth를 shared `PlayerLocomotionCore`로 계산하고 있었지만, 그 결과를 host 화면의 remote avatar animator까지 항상 반영하지는 않았다.
* 이 때문에 attack/dash처럼 `Full` FSM fallback에서 직접 `CrossFade` 하는 액션은 보이는데, move-only idle/walk는 host 화면에서 빠질 수 있었다.

### 무엇을 수정했는가
* `Assets/Scripts/Multiplayer/Gameplay/MultiplayerPlayerAvatar.cs`
  * Host authority locomotion tick에서 shared locomotion sim 호출 시 `updateAnimator=true` 로 바꿨다.
  * `EnterAuthoritativeLocomotionMode()` 진입 시 `Locomotion` 으로 `CrossFade` 하고 current input magnitude로 `Speed` 를 바로 맞추도록 보강했다.

### 왜 그렇게 판단했는가
* locomotion math, rollback, correction threshold를 건드리지 않고도 host-side visual gap만 좁게 복구할 수 있는 가장 안전한 수정이었다.
* 문제의 범위가 `move-only authority path` 에만 모여 있었기 때문에, special path 안에서 animator sync를 복구하는 편이 회귀 위험이 가장 낮다.
