## 맥락노트
* current repo는 `.git/info/exclude`, `skip-worktree`, ignored vendor packs 때문에 plain `git diff`만으로 asset export 대상을 신뢰하기 어렵다.
* 그래서 이번 foundation은 “Git이 지금 보여 주는 것”이 아니라 “repo가 허용한 root 중 branch가 관리해야 하는 것”을 먼저 명시하는 방향으로 잡았다.
* same reason으로 `Assets/Resources/**`는 generic art bucket으로 재사용하지 않고, audited runtime exception만 special root로 따로 관리하도록 분리했다.

## 기술적 고려
### 무엇을 발견했는가
* current branch asset maintenance는 Git visible diff보다 repo allowlist가 더 신뢰도 높은 source였다.
* current workspace에서 runtime prefab resource root는 `Assets/Resources/Prefabs`였고, `Assets/Resources/Multiplayer`는 실제 on-disk root가 아니었다.
* Unity batch validation을 막는 첫 문제는 shell env(`HOME`/`LOCALAPPDATA`/`APPDATA`) 누락이었고, 그 다음 문제는 repo 기존 Beautify/test assembly compile error였다.

### 무엇을 수정했는가
* gradual folder convention root(`Assets/Project/Logic`, `Assets/Project/Content`)를 추가했다.
* repo-tracked export config와 PowerShell orchestrator, Unity batch export bridge를 구현했다.
* export naming contract를 `<branch_slug>_delta_unity_assets_<YYYYMMDD>.unitypackage`, `<branch_slug>_raw_downloads_<YYYYMMDD>.zip`, `<branch_slug>_manifest_<YYYYMMDD>.md`로 고정했다.
* special `Resources` root를 `Assets/Resources/Prefabs`로 바꿔 current project reality에 맞췄고, placeholder recovery script exclude를 config에 반영했다.
* batch wrapper에 env fallback + `-noUpm`를 추가해 environment-side false failure를 줄였다.

### 왜 그렇게 판단했는가
* user 목표는 “code/docs는 Git, big/uncommitted assets는 branch export artifact”이므로, export workflow는 branch-owned asset set을 독립적으로 재생성할 수 있어야 했다.
* empty folder convention만 먼저 만들고 기존 asset 이동은 미룬 이유는, current branch가 already dirty하고 art/reference risk가 커서 immediate bulk move가 maintenance cost보다 risk가 더 컸기 때문이다.
* validation은 성공만 적지 않고 fail point까지 기록해야 다음 maintenance turn이 바로 이어질 수 있으므로, current compile blockers도 progress log에 같이 남겼다.
