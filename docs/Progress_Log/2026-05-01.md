## 맥락노트
* 사용자 목표는 multiplayer gameplay에서 host player가 client look이 아니라 host look을 가지게 만드는 것이었다.
* 실제 원인은 `IsHost`/`IsClient` branch보다 앞선 visual source 선택에 있었다. host branch는 맞았지만, shared network prefab default visual이 client-style source를 계속 들고 있었다.
* 그래서 scene object 이름이나 runtime prefab fallback을 더 이상 믿지 않고, `Visual_replaced`를 가리키는 explicit host visual source를 config에서 직접 읽는 구조로 좁혀서 수정했다.
* 같은 날 이어진 solo player visible bug 조사에서는 `TitleScene`의 solo click이 multiplayer title driver path를 타고 shared gameplay scene으로 바로 들어가지만, shared scene 안에는 `SoloPlayerAvatar`만 켜는 explicit bootstrap이 보이지 않았다. 그래서 먼저 `[SoloDebug]` 로그로 title click, gameplay scene start, local input enable, player runtime role을 동시에 관측할 수 있게 진단 표면을 만들었다.
* 그 다음 multiplayer verify에서는 host/client runtime player에 `SoloPlayerAvatar` visual이 붙는 회귀가 확인됐다. shared gameplay scene template avatar는 spawn marker로만 남아야 하므로, multiplayer active session에서는 scene template root가 항상 disabled 상태를 유지해야 했다.
* 같은 날 combat verify에서는 host/client player가 공격 애니메이션은 재생되는데 boss hit confirm이 빠지는 구간과, visual swap 뒤 client 화면에서 host 이동 애니메이션이 stale animator cache 때문에 갱신되지 않는 구간, 그리고 client boss 피격 시 white blink가 빠지는 구간이 함께 확인됐다.

## 기술적 고려
### 무엇을 발견했는가
* host/client role branch 자체는 정상이었지만, host visual source가 shared prefab default child 쪽으로 기울어 있어 host도 client-style visual을 잡고 있었다.
* `SoloPlayerAvatar` scene marker 이름이나 `HostPlayerAvatarPrefab` fallback만으로는 실제 host look source가 `Visual_replaced`인지 보장되지 않았다.
* 따라서 문제의 핵심은 network authority가 아니라 host visual source-of-truth 부재였다.
* solo player visible bug 조사에서는 `Assets/Scenes/mutiplayer/GamePlayScene.unity`의 `SoloPlayerAvatar`와 `MultiPlayerAvatar`가 둘 다 scene authored state에서 inactive이고, multiplayer scene prep는 active session이 있을 때만 동작하는 점을 확인했다. 즉 solo path에는 shared scene avatar on/off를 명시적으로 정리하는 전용 bootstrap이 필요할 가능성이 높았다.
* multiplayer follow-up에서는 active session일 때 scene template avatar가 preserve path 또는 late activation path를 타면, host/client runtime player 위에 잘못된 `SoloPlayerAvatar` visual이 남을 수 있다는 점이 드러났다. 이 scene template object는 multiplayer에서 live player가 아니라 marker-only disabled root여야 한다.
* combat follow-up에서는 shared player prefab의 visual swap 이후 `_damageCaster` reference와 `NetworkAnimator` 내부 파라미터 캐시가 current active visual 기준으로 stale 상태가 될 수 있어, boss hit 누락과 host movement 미표시가 함께 발생할 수 있었다.
* boss hit replay는 `MultiplayerBossAuthorityBridge`에서 `BossVisual.TriggerHit()`만 호출해 피격 모션은 보이지만, `BlinkWhiteEffect` one-shot은 host/client 공통 경로로 묶여 있지 않아 client side blink가 누락될 수 있었다.

### 무엇을 수정했는가
* `MultiplayerRuntimeConfig`에 explicit `HostVisualTemplate` field를 추가하고, asset에서 `SoloPlayerAvatar/Visual_replaced`를 직접 참조하게 했다.
* `MultiplayerPlayerAvatar.CacheHostVisualReference()`가 먼저 `HostVisualTemplate`를 읽어 runtime `HostVisual` child를 만들고, presentation reference와 embedded camera disable도 same path에서 처리하도록 정리했다.
* old fallback visual은 host source가 확정된 뒤 비활성화해, runtime visual rebinding이 stale shared child를 다시 잡지 않게 했다.
* solo bug용으로 `MultiplayerTitleSceneDriver.HandleSoloPlaySelected()`, `GameManager.Start()`, `LocalInputProvider.OnEnable()/SetRuntimeInputEnabled()`, `PlayerController.Start()`에 `[SoloDebug]` 로그를 추가했다. 로그는 scene path, `HasActiveSession`, `SoloPlayerAvatar`/`MultiPlayerAvatar` active state, input enable, simulation mode, authority mode, HP를 함께 남긴다.
* `GameManager`는 no active session + shared gameplay scene 조합에서만 `SoloPlayerAvatar`를 활성화하고 `MultiPlayerAvatar`는 비활성화하는 solo bootstrap guard를 갖게 했다.
* `MultiplayerGameplaySceneCoordinator`는 active multiplayer session이 시작되면 scene root `SoloPlayerAvatar`/`MultiPlayerAvatar`를 먼저 비활성화하고, 그 뒤 runtime spawn/legacy cleanup을 계속 진행하게 했다.
* `MultiplayerPlayerAvatar` scene-object path는 active multiplayer session 중 `SoloPlayerAvatar`/`MultiPlayerAvatar` template를 preserve하지 않고 즉시 비활성화하도록 guard를 추가했다.
* `PlayerController`는 `ResolveDamageCasterBinding()`/`RebindDamageCaster()` 경로로 active visual 아래 `DamageCaster`를 우선 재탐색하고 owner/event binding을 다시 연결하도록 정리했다.
* `MultiplayerPlayerAvatar`는 visual rebind 직후 `NetworkAnimator`의 non-public `Awake()`를 reflection으로 다시 호출해 내부 animator parameter cache를 현재 active animator 기준으로 재생성하도록 보강했다.
* `BossController`는 `PlayDamageBlinkVisual()`을 public helper로 분리해 host damage path와 client replay path가 같은 white blink 진입점을 사용하게 했고, bridge hit replay에서 same helper를 호출하도록 연결했다.
* nullable `IsSceneObject` 비교는 `!= true`로 맞춰 compile error를 제거했다.

### 왜 그렇게 판단했는가
* host look bug는 wrong branch보다 wrong source일 가능성이 더 컸고, 실제 진단 결과도 그 방향과 일치했다.
* explicit config source 하나로 host visual truth를 고정하면 scene marker naming, prefab default child order, shared prefab default look에 덜 의존하게 된다.
* client visual flow를 건드리지 않고 host source만 분리하면 regression 범위를 가장 작게 유지할 수 있다.
* solo issue는 바로 기능 코드를 바꾸기보다, shared title/gameplay path에서 어떤 object가 언제 활성화되고 input을 받는지 먼저 확인해야 회귀 범위를 줄일 수 있었다. 그래서 runtime behavior를 좁게 읽을 수 있는 temporary trace를 먼저 추가했다.
* solo fix는 `GameManager`의 no active session guard 하나로 한정해 shared scene authored state를 직접 뒤집지 않도록 했고, multiplayer fix는 scene template avatar disable을 `MultiplayerGameplaySceneCoordinator`와 `MultiplayerPlayerAvatar` 두 지점에서 보강해 host/client runtime avatar를 건드리지 않으면서 marker-only contract를 유지하도록 판단했다.
* boss hit/host movement/client blink 세 문제는 모두 "visual swap 뒤 stale runtime binding" 성격이라, prefab serialized 값을 다시 고정하기보다 runtime에서 active visual 기준 binding/cache를 재생성하고, hit replay visual 진입점을 host/client 공통 helper로 통합하는 편이 회귀 범위를 가장 작게 유지할 수 있었다.
