# 2026-05-01 (금): multiplayer host visual explicit template source fix

## 오늘 반영한 작업
* `Assets/Scripts/Multiplayer/Runtime/MultiplayerRuntimeConfig.cs`에 `_hostVisualTemplate` 직렬화 필드와 `HostVisualTemplate` 접근자를 추가했다.
* `Assets/Resources/MultiplayerRuntimeConfig.asset`에서 `_hostVisualTemplate`를 `SoloPlayerAvatar/Visual_replaced` source로 직접 연결했다.
* `Assets/Editor/MultiplayerRuntimeConfigEditor.cs`에서 `Host Visual Template`를 인스펙터에 노출해, runtime config가 어떤 host visual source를 가리키는지 editor에서 바로 확인할 수 있게 했다.
* `Assets/Scripts/Multiplayer/Gameplay/MultiplayerPlayerAvatar.cs`에서 host visual 선택을 shared prefab child 탐색에 맡기지 않고, configured `HostVisualTemplate`를 runtime child `HostVisual`로 복제해 쓰도록 바꿨다.
* host visual을 적용할 때 old fallback visual은 비활성화하고, client visual flow는 그대로 유지해 client look regression 없이 host만 host look을 갖도록 정리했다.

## 맥락노트
* 사용자 목표는 multiplayer gameplay에서 host player가 client look이 아니라 host look을 가지게 만드는 것이었다.
* 실제 원인은 `IsHost`/`IsClient` branch보다 앞선 visual source 선택에 있었다. host branch는 맞았지만, shared network prefab default visual이 client-style source를 계속 들고 있었다.
* 그래서 scene object 이름이나 runtime prefab fallback을 더 이상 믿지 않고, `Visual_replaced`를 가리키는 explicit host visual source를 config에서 직접 읽는 구조로 좁혀서 수정했다.

## 기술적 고려
### 무엇을 발견했는가
* host/client role branch 자체는 정상이었지만, host visual source가 shared prefab default child 쪽으로 기울어 있어 host도 client-style visual을 잡고 있었다.
* `SoloPlayerAvatar` scene marker 이름이나 `HostPlayerAvatarPrefab` fallback만으로는 실제 host look source가 `Visual_replaced`인지 보장되지 않았다.
* 따라서 문제의 핵심은 network authority가 아니라 host visual source-of-truth 부재였다.

### 무엇을 수정했는가
* `MultiplayerRuntimeConfig`에 explicit `HostVisualTemplate` field를 추가하고, asset에서 `SoloPlayerAvatar/Visual_replaced`를 직접 참조하게 했다.
* `MultiplayerPlayerAvatar.CacheHostVisualReference()`가 먼저 `HostVisualTemplate`를 읽어 runtime `HostVisual` child를 만들고, presentation reference와 embedded camera disable도 same path에서 처리하도록 정리했다.
* old fallback visual은 host source가 확정된 뒤 비활성화해, runtime visual rebinding이 stale shared child를 다시 잡지 않게 했다.

### 왜 그렇게 판단했는가
* host look bug는 wrong branch보다 wrong source일 가능성이 더 컸고, 실제 진단 결과도 그 방향과 일치했다.
* explicit config source 하나로 host visual truth를 고정하면 scene marker naming, prefab default child order, shared prefab default look에 덜 의존하게 된다.
* client visual flow를 건드리지 않고 host source만 분리하면 regression 범위를 가장 작게 유지할 수 있다.
