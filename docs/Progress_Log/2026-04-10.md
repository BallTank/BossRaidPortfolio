# 2026-04-10 (금): basic/lunge player-hit trace instrumentation and rollback

## 오늘 반영한 작업
* `AttackWarningController`에 boss hit trace 로그를 추가했다.
* trace는 Attack1/Attack2를 `Basic`/`Lunge` 라벨로 출력하고, warning zone 판정(`PASS`/`FAIL`)과 receiver resolution 결과를 함께 남긴다.
* `PlayerController.ReceiveBossAttackHit(...)`에 gate-by-gate trace를 추가했다.
* player trace는 authority gate, health gate, stun/invul gate, 공격 타입별 damage apply 결과, 최종 resolution을 순서대로 출력한다.
* follow-up으로 `PlayerController` trace guard를 `enableBossHitTraceLog || Application.isEditor`로 보강해, scene/prefab 직렬화 값이 꺼져 있어도 Editor 재현에서는 로그가 보이게 했다.
* follow-up으로 `AttackWarningController`에 `ActivePhaseStart` 및 `Sector/Strip` 물리 쿼리 요약(`hitCount`, `playerCandidates`) trace를 추가했다.
* 사용자 요청으로 `BossHitTrace` / `PlayerBossHitTrace` debug instrumentation을 모두 롤백했다.
* 사용자 요청으로 `S05~S12` 단계 추적용 no-toggle 콘솔 로그를 `AttackWarningController`, `PlayerController`, `Health`에 추가했다.
* follow-up으로 `Core.Common.HitTraceLogger`를 추가해 `HitTrace`를 콘솔 Warning + `Application.persistentDataPath/HitTrace.log` 파일에 동시 기록하도록 보강했다.
* follow-up으로 `RuntimeInitializeOnLoad(AfterAssembliesLoaded)` BOOT trace를 추가해, gameplay 진입 전 logger 활성 여부를 먼저 확인할 수 있게 했다.
* follow-up으로 warning close-cause 추적을 위해 `BossController.HideBasicAttackTelegraph/HideLungeAttackTelegraph(reason)`, `AttackWarningController.ForceEnd(reason)`, `FinishPlayback(reason)` 로그를 추가했다.
* follow-up으로 `HideBasic/LungeAttackTelegraph` pre-active 호출은 즉시 `ForceEnd`하지 않고 `DEFER_PREACTIVE`로 넘기도록 바꿨다. 이를 통해 active phase 진입 전 warning이 사라져 damage가 누락되는 회귀를 막았다.
* follow-up으로 `LungeAttackPattern` close 경로에 one-shot apply guard를 추가해 같은 `Lunge.CloseDamageWindow` hide 호출이 프레임마다 반복되는 스팸을 차단했다.
* follow-up으로 Basic timing 정합을 위해 `BasicAttackPattern`이 `readyNormalizedWindow.y` 경계를 넘는 즉시 `BossController.TryEnterBasicAttackTelegraphActiveNow(...)`를 호출하도록 변경했다. 이제 Attack1 one-shot damage open이 warning seconds 타이머가 아니라 ready normalized 경계에 직접 맞춰진다.
* 관련 문서(`Progress_Log/README`, `System_Blueprint`, `Technical_Glossary`)를 현재 trace 계약에 맞게 동기화했다.

## 기술적 고려
### 무엇을 발견했는가
* Attack1/Attack2는 same `AttackWarningController -> IBossAttackHitReceiver` 경로를 공유해서, warning zone mismatch와 receiver gate ignore를 분리해 봐야 원인을 빠르게 좁힐 수 있었다.
* `AttackWarningController`에서 `Ignored`가 반복될 때는 continuous window에서 로그가 과도하게 늘어날 수 있었다.

### 무엇을 수정했는가
* `AttackWarningController`에 `[BossHitTrace]` 로그를 추가해 다음 정보를 출력하도록 했다.
* attack type label(`Basic`/`Lunge`)
* warning zone `PASS`/`FAIL`
* target filter 결과
* `ReceiveBossAttackHit` resolution
* `Ignored` 반복 로그는 player 단위 1회로 제한했다.
* `PlayerController`에 `[PlayerBossHitTrace]` 로그를 추가해 다음 단계를 출력하도록 했다.
* `AuthorityGate`
* `HealthGate`
* `StateGate`
* attack-type damage apply 단계
* `FinalResolution`
* follow-up으로 `PlayerController` trace gate를 Editor 강제 허용으로 바꿨고, `AttackWarningController`는 active phase 시작/물리쿼리 요약 로그를 추가했다.
* 사용자 요청 follow-up으로 기존 trace toggle 구조 대신 no-toggle `HitTrace` 로그를 추가했다.
* `AttackWarningController`: `S05 ResolveDamageable`, `S06 TargetFilter`, `S07 ReceiverCall/Resolution`, `S12 IgnoredNoFallback` 로그
* `PlayerController`: `S08 ReceiveEnter/Exit`, `S09 Gate 결과`, `S10 HP before/after` 로그
* `Health`: `S11` early-return reason(`NoWriteAuthority`, `AlreadyDead`, `Invincible`, `NonPositiveDamage`) 로그
* `BasicAttackPattern`은 `readyNormalizedWindow.y` crossing을 1회 감지해 `BossController.TryEnterBasicAttackTelegraphActiveNow(...)`를 호출하고, `AttackWarningController.EnterActivePhase()`를 즉시 열도록 변경했다.

### 왜 그렇게 판단했는가
* 원인 분리가 끝나기 전에 damage window를 다시 튜닝하면 regression surface가 넓어진다.
* 따라서 first step은 "same frame에서 zone 판정과 receiver gate를 함께 보는 것"이 가장 안전하고 빠른 디버깅 경로라고 판단했다.
