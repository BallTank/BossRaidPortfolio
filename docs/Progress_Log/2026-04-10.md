## 기술적 고려
### 무엇을 발견했는가
* Attack1/Attack2는 same `AttackWarningController -> IBossAttackHitReceiver` 경로를 공유해서, warning zone mismatch와 receiver gate ignore를 분리해 봐야 원인을 빠르게 좁힐 수 있었다.
* `AttackWarningController`에서 `Ignored`가 반복될 때는 continuous window에서 로그가 과도하게 늘어날 수 있었다.

### 무엇을 수정했는가
* `AttackWarningController`에 `[BossHitTrace]` 로그를 추가해 다음 정보를 출력하도록 했다.
* attack type label(`Basic`/`Lunge`)
* warning zone `PASS`/`FAIL`
* target filter 결과
* `ReceiveBossAttackHit` resolution
* `Ignored` 반복 로그는 player 단위 1회로 제한했다.
* `PlayerController`에 `[PlayerBossHitTrace]` 로그를 추가해 다음 단계를 출력하도록 했다.
* `AuthorityGate`
* `HealthGate`
* `StateGate`
* attack-type damage apply 단계
* `FinalResolution`
* follow-up으로 `PlayerController` trace gate를 Editor 강제 허용으로 바꿨고, `AttackWarningController`는 active phase 시작/물리쿼리 요약 로그를 추가했다.
* 사용자 요청 follow-up으로 기존 trace toggle 구조 대신 no-toggle `HitTrace` 로그를 추가했다.
* `AttackWarningController`: `S05 ResolveDamageable`, `S06 TargetFilter`, `S07 ReceiverCall/Resolution`, `S12 IgnoredNoFallback` 로그
* `PlayerController`: `S08 ReceiveEnter/Exit`, `S09 Gate 결과`, `S10 HP before/after` 로그
* `Health`: `S11` early-return reason(`NoWriteAuthority`, `AlreadyDead`, `Invincible`, `NonPositiveDamage`) 로그
* `BasicAttackPattern`은 `readyNormalizedWindow.y` crossing을 1회 감지해 `BossController.TryEnterBasicAttackTelegraphActiveNow(...)`를 호출하고, `AttackWarningController.EnterActivePhase()`를 즉시 열도록 변경했다.
* refactor 단계에서 임시 추적 로그(`HitTraceLogger` + `S05~S12` 출력)는 모두 제거하고, 실제 판정 동작(ready-end active open, pre-active hide defer, lunge close one-shot guard)은 유지했다.
* 이번 수정에서는 local hitbox callback에 의존하던 HUD update를 host authoritative result packet으로 분리했다. owner client는 local `OnAttackHitConfirmed/OnAttackWindowResolved`가 없어도 server가 승인한 hit 결과를 즉시 HUD에 반영한다.
* root cause는 host가 damage resolve 시점의 `LastAcceptedComboIndex`를 읽어 HUD `comboStep`를 다시 만들던 점이었다. 다음 combo approval이 먼저 기록되면 이전 attack hit가 step `2/3`으로 잘못 라벨링될 수 있었다.
* fix에서는 `PlayerController.OnHitStart()`가 current attack combo step을 `_activeAttackWindowComboStep`으로 캡처하고, `HandleAttackWindowResolved()`가 same captured step을 `AttackDamageResolved(totalDamage, comboStep)`으로 전달한다. Host는 이 event payload를 그대로 `PushAttackHitFeedbackClientRpc(...)`에 사용한다.
* timing verify가 끝난 뒤에는 temporary trace helper와 `[ComboTimingDebug]` 출력만 제거하고, hit-window captured combo step 기반 functional fix는 그대로 유지했다.
* integration merge follow-up root cause는 art branch merge 결과가 `Packages/manifest.json`에서 multiplayer package references를 제거한 점이었다. `docs/temp_console_log.txt`에 남은 `Unity.Netcode`, `Unity.Services.Authentication`, `Unity.Services.Lobbies`, `Unity.Services.Relay`, `UnityTransport` missing namespace는 runtime code regression이 아니라 package graph regression으로 해석하는 편이 맞았다.
* fix에서는 art-side package add-on은 유지한 채 `com.unity.netcode.gameobjects`, `com.unity.transport`, `com.unity.services.authentication`, `com.unity.services.lobby`, `com.unity.services.relay`와 dependent `packages-lock` entries를 다시 넣었다. Unity Editor가 current manifest를 다시 읽으면 generated `.csproj`와 assembly reference가 따라와야 한다.
* art scene follow-up에서는 `docs/temp_console_log.txt`가 실제로는 missing namespace만이 아니라 missing prefab/model/script reference도 같이 보여 주고 있음을 확인했다. `GamePlayScene_Art.unity` 기준 unresolved GUID를 직접 스캔해 보니 남은 hard error는 mostly legacy art asset + missing MonoScript reference였다.
