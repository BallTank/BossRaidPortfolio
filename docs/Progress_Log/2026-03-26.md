## 기술적 고려
### 무엇을 발견했는가
* custom deterministic motor / shared pure-sim pass는 `going down + jitter` feedback을 남겼고, solo와 multiplayer movement truth가 갈라지는 문제가 더 컸다.
* 이 branch에서 `CharacterController` 자체가 main problem이라기보다, `Host authority + immediate client feel + same solo movement truth`를 동시에 맞추는 것이 어려운 문제에 더 가깝다.
* current reset 뒤에도 visible jitter는 남았고, 이는 owner가 Host authoritative root 변화를 그대로 보게 되는 presentation 문제로 더 좁혀졌다.
* reference review 기준으로는 `Boss Room`이 `keep gameplay truth authoritative, hide latency on presentation/camera` 방향에서 가장 잘 맞았다.

### 무엇을 수정했는가
* `MultiplayerPlayerAvatar`의 current active path는 그대로 Host-only authoritative fallback으로 유지했다.
* `PlayerController`에는 local owner visual child position smoothing, presentation rotation 유지, preferred camera follow position 계산, masking reset/cache helper를 추가했다.
* 같은 masking layer 안에서 `idle -> move start` transition은 smooth catch-up 대신 immediate body snap을 사용하도록 보강했다.
* `strong move-angle change` response window 실험은 local client에서 jitter를 더 키웠기 때문에 current active path에서는 다시 제거했다.
* 그 다음 follow-up은 direction-change position response를 다시 넓히지 않고, `LookOnly` local owner의 animator `Speed` 반응과 large-angle body facing response만 좁게 빠르게 만드는 쪽으로 제한했다.
