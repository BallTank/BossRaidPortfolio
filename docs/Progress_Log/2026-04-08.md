### 기술적 고려
#### 무엇을 발견했는가
* local `MoveState`는 keyboard normalized input magnitude를 즉시 `Animator Speed`에 써서 opposite turn neutral frame에서 idle pop이 생기고 있었다.
* multiplayer-related locomotion path도 `Speed` write 지점이 분산돼 있어, local-only patch를 하면 viewer path마다 다른 feel이 생길 risk가 있었다.
* actual move physics를 바꾸지 않아도 `Animator.SetFloat(..., dampTime, deltaTime)`만으로 short idle cut-in을 줄일 수 있었다.

#### 무엇을 수정했는가
* `PlayerController.SetLocomotionAnimatorSpeed(...)` helper를 추가해 clamped value, zero/instant fallback, damping 적용을 한 곳에서 처리하게 했다.
* `MoveState`, `PlayerLocomotionCore`, `MultiplayerPlayerAvatar`가 direct `SetFloat` 대신 same helper를 호출하도록 바꿨다.
* tuning 값은 inspector에서 바로 조절할 수 있게 serialized field로 노출했다.

#### 왜 그렇게 판단했는가
* user가 원한 것은 control feel 변화가 아니라 idle cut-in 제거였으므로, animation parameter smoothing이 가장 low-risk answer였다.
* helper 하나로 write path를 모으면 solo/multiplayer locomotion presentation이 같은 rule을 공유해 later maintenance cost가 낮아진다.
* default `0.08f`는 `0.05~0.12s` 목표 범위 안에서 sharp feel과 visual stability를 균형 있게 시작하기 좋은 값이다.
