## 기술적 고려
### 무엇을 발견했는가
* `PlayerController`와 `BossController`는 serialized field가 많지만, 그중 일부는 HUD/runtime/debug/reference 성격이라 generic dump를 하면 balance file이 쉽게 오염된다.
* `Health`는 runtime에서 `_currentHealth`를 직접 소비하지만, balance source-of-truth로는 `_maxHealth`만 안정적이다.
* boss attack setting은 nested serializable class로 묶여 있어 CSV보다 JSON이 훨씬 안전하다.

### 무엇을 수정했는가
* editor window에서 JSON path, prefab target, scene target, export source를 직접 고를 수 있게 했다.
* serialized-property 기반 mapper를 추가해 player/boss balance field만 capture/apply 하도록 만들었다.
* scene import는 verify scene을 열어 player/boss를 찾아 적용 후 저장하고, prefab import는 prefab contents editing 경로로 저장하도록 분리했다.

### 왜 그렇게 판단했는가
* balance tool의 목적은 tuning value portability이므로, current HP나 runtime gate까지 함께 옮기면 file meaning이 흐려진다.
* mixed asset/scene workflow가 current project 상태에 맞기 때문에, hardcoded one-path tool보다 drag-and-drop window가 later prefab migration에도 덜 깨진다.
* JSON은 nested attack setting, combo array, future schema extension까지 한 번에 다루기 쉬워 later maintenance cost가 가장 낮다.
