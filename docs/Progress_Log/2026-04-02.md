## Topic 1. editor/build connection pulse debug

## 오늘 반영한 작업
* old edge-only connection debug를 걷어내고 `[MultiplayerConnectionDebug]`를 `editor/build + host/client` 기준의 clean structured logger로 다시 정리했다.
* `peer-connect`, `peer-disconnect`, `state-change`, `gameplay-sync-complete`, `pulse` event를 한 prefix로 통일하고, line마다 `state`, `scene`, `localClientId`, `isServer`, `isClient`, `isConnected`, `isListening`, `shutdown`, `hostPeerCount`, `lobbyPlayers`를 함께 남기도록 바꿨다.
* client app에서는 NGO server-only API(`ConnectedClientsIds`)를 더 이상 읽지 않도록 바꿔 logger 자체가 `NotServerException`을 만들지 않게 했다.
* `MultiplayerPlayerAvatar`는 disconnect용 입력 프로파일을 `avatar-profile-baseline`, `avatar-profile-transition` event로 바로 남기고, disconnect summary는 `noActionObservedAffected` 플래그와 avatar profile dump를 같이 붙이도록 정리했다.

## 체크리스트 업데이트

* [x] avatar input profile baseline / transition log를 추가해 `idle-only` / `idle-walk-only` / `action-observed` 진행을 disconnect 이전부터 증명할 수 있게 했다.
* [x] `dotnet build Assembly-CSharp.csproj`로 코드 검사를 통과했다.

## 맥락노트
* 기존 조사 결과 remote action-intent RPC 자체는 Host에 도착하고 있었고, 후반부 문제는 session continuity / disconnect handling 쪽으로 무게가 이동했다.

* 이번 변경은 gameplay behavior를 바꾸지 않고, disconnect 순간뿐 아니라 disconnect 전후 continuity까지 host/client 각 앱 로그에서 읽기 쉽게 만드는 데 초점을 맞췄다.

## 기술적 고려
### 무엇을 발견했는가
* edge-only connect/disconnect 로그만으로는 continuity가 중간에 언제 깨졌는지 보장 있게 측정하기 어려웠다.
* client app debug가 server-only API를 읽으면서 `NotServerException`을 만들고 있어, logger 자체가 테스트를 오염시키고 있었다.
* `idle/walk-only` run 여부도 disconnect 순간 한 줄만으로는 충분히 증명되지 않았다.

### 무엇을 수정했는가

* 관련 문서 설명을 current logger contract 기준으로 다시 맞췄다.

### 왜 그렇게 판단했는가
* 지금 필요한 것은 행동 수정이 아니라, `Editor log + build log` 두 개만으로 continuity 상태를 비교할 수 있는 관측값이다.
* session continuity 버그는 단발 disconnect edge보다 `그 직전까지 연결이 살아 있었는가`가 더 중요하므로, low-rate pulse와 state-change를 같이 남기는 편이 더 신뢰할 만하다.
* `idle/walk-only` 여부는 disconnect 때 한 번 붙이는 요약보다, avatar profile이 baseline에서 어떤 단계로 올라갔는지를 함께 남겨야 원인 구분이 더 빠르다.

## Topic 2. remote action validation from Host buffered input

## 오늘 반영한 작업
* remote `Dash/Attack` authority를 separate action RPC가 아니라 Host의 owner input uplink receive 시점에서 처리하도록 바꿨다.

* separate `SubmitOwnerActionIntentServerRpc(...)`는 Host truth를 만들지 않고 `rpc-received` trace만 남기도록 정리했다.

* [x] `dotnet build Assembly-CSharp.csproj`로 코드 검사를 통과했다.
* [x] `Progress_Log`, `System_Blueprint`, `Technical_Glossary`를 동기화했다.

## 맥락노트
* 기존 구조는 client가 따로 보내는 action RPC에 Host validation이 묶여 있어, remote player가 로컬에서 action을 눌러도 Host truth가 따라오지 않는 run이 있었다.
* locomotion input uplink는 이미 Host가 매 packet 받는 main path이므로, action authority도 same receive point에서 edge를 잡는 편이 더 안전하다.

## Topic 3. StartingGameplay -> InGameplay state split

## 오늘 반영한 작업
* `MultiplayerSessionService`에 `InGameplay` session state를 추가해 `StartingGameplay`를 real startup handoff 전용 상태로만 쓰도록 분리했다.
* Host는 gameplay scene sync 완료 후 authoritative player spawn을 끝내면 바로 `InGameplay`로 넘어가고, lobby session state도 `InGame`으로 publish하도록 바꿨다.
* late disconnect는 더 이상 `Client disconnected during gameplay start.`로 뭉뚱그리지 않고, runtime gameplay 구간에서는 `Client disconnected during gameplay.`로 분리했다.
* connection pulse / status text도 `InGameplay`를 인식하도록 정리해, gameplay sync가 끝난 뒤에도 `Starting game...`가 계속 남지 않게 했다.

* [x] gameplay sync 완료 직후 Host state가 `InGameplay`로 넘어가게 했다.
* [x] late disconnect message를 startup disconnect와 runtime disconnect로 분리했다.

## 맥락노트

## Topic 4. guaranteed peer-disconnect logger

## 오늘 반영한 작업
* `HandleNetworkClientDisconnected(...)`의 disconnect logger를 `peer-disconnect -> peer-disconnect-detail -> peer-disconnect-fallback` 구조로 나눴다.
* callback entry에서는 avatar profile dump 없이 작은 `peer-disconnect` edge line을 먼저 바로 찍고, profile-heavy line은 `peer-disconnect-detail`로 분리했다.
* detail 수집이 실패해도 disconnect edge 자체는 남도록 `try/catch`로 감싸고, shutdown 직전에는 cached snapshot으로 `peer-disconnect-fallback` line을 한 번 더 남기도록 보강했다.
* normal lobby disconnect처럼 shutdown으로 이어지지 않는 경우에는 cached disconnect snapshot을 즉시 비워 later shutdown에 stale fallback이 찍히지 않게 정리했다.

## 체크리스트 업데이트
* [x] exact disconnect edge를 small line으로 먼저 남기도록 분리했다.
* [x] avatar profile dump를 separate detail line으로 분리했다.
* [x] shutdown 직전 fallback disconnect line을 추가했다.
* [x] `dotnet build Assembly-CSharp.csproj`로 코드 검사를 통과했다.
* [x] `Progress_Log`, `System_Blueprint`, `Technical_Glossary`를 동기화했다.

## 맥락노트
* 기존 로그에서는 real disconnect message와 `Closing` state-change 사이에 있어야 할 exact `peer-disconnect` line이 빠지는 run이 있었다.
* 이번 slice는 disconnect 원인 자체를 해결하는 것이 아니라, disconnect edge가 shutdown noise에 묻혀도 log export에서 반드시 다시 읽히게 만드는 것이 목적이다.

## 기술적 고려
### 무엇을 발견했는가
* 기존 disconnect logger는 `peer-disconnect` line 하나에 extra profile dump까지 같이 싣고 바로 shutdown 경로로 들어갔다.
* 이 구조에서는 disconnect edge가 shutdown/export 타이밍에 빠지면 exact disconnect 순간을 증명할 line이 없어졌다.

### 무엇을 수정했는가
* callback entry에서 minimal `peer-disconnect` edge line을 먼저 쓰도록 바꿨다.
* avatar profile dump는 `peer-disconnect-detail` line으로 분리하고, detail 수집 실패 시 `peer-disconnect-detail-failed` line으로 남기도록 했다.
* shutdown 직전 cached snapshot 기반 `peer-disconnect-fallback` line을 추가하고, non-fatal disconnect에서는 snapshot을 즉시 clear하도록 정리했다.

### 왜 그렇게 판단했는가
* disconnect 조사에서 가장 중요한 것은 `disconnect edge가 실제로 언제 발생했는가` 이므로, first line은 작고 즉시 기록되어야 한다.
* profile dump는 useful context지만 edge보다 중요하지 않으므로 second line으로 분리하는 편이 더 안전하다.
