# 2026-04-14 (화): branch asset export lock preflight

## 오늘 반영한 작업
* `tools/asset_export/Export-BranchAssetArtifacts.ps1`의 Unity batch launch path에서 `-noUpm` 옵션을 제거해 current package graph를 normal path로 해석하게 정리했다.
* same script에 `Temp/UnityLockfile`, `Library/SourceAssetDB-lock`, `Library/ArtifactDB-lock` preflight를 추가해 project가 이미 Unity Editor에서 열려 있으면 batch export를 시작하기 전에 명확한 안내와 함께 중단하게 만들었다.
* same script의 environment fallback에 `PROGRAMDATA`/`ALLUSERSPROFILE` 보강을 추가하고, `USERPROFILE` drive root 기준 `ProgramData` fallback까지 연결해 Unity Package Manager local server가 automation shell에서도 `ProgramData/Unity/config` 경로를 정상 해석하게 만들었다.
* same script가 Unity batch launch 전에 `UnityPackageManager.exe`를 직접 IPC mode로 prestart하고, Unity에 `-upmIpcPath`를 넘겨 재사용하게 만들어 batch export가 local UPM bootstrap timeout 없이 끝까지 진행되게 만들었다.
* raw zip helper에 `System.IO.Compression` assembly load를 보강해 `.zip` 생성이 중간에 type load error로 멈추지 않게 고쳤다.
* current batch export failure root cause가 existing compile blocker가 아니라 open-project lock이라는 점을 validation 결과와 문서에 반영했다.
* `Progress_Log`, `System_Blueprint`, `Technical_Glossary`를 이번 workflow maintenance 기준으로 동기화했다.

### 무엇을 발견했는가
* previous batch failure를 compile blocker처럼 읽었지만, current repo에서는 project-open lock이 먼저 걸리면 Unity batchmode가 misleading crash/error log를 남길 수 있었다.
* `-noUpm` 옵션은 current branch가 의존하는 URP/Test package assembly resolve를 불필요하게 비정상 경로로 돌릴 수 있었다.
* lock issue를 지나간 뒤에는 Unity Package Manager server가 `process.env.PROGRAMDATA`를 직접 읽고 있어, automation shell에서 이 값이 비어 있으면 Node side에서 `path.join(undefined, "Unity", "config")` 예외로 바로 죽는다는 점을 확인했다.
* same machine에서는 Unity가 child process로 UPM을 자동 bootstrap할 때 IPC connect timeout이 다시 날 수 있었고, raw archive 단계에서는 `System.IO.Compression` assembly가 load되지 않아 `ZipArchiveMode` type resolve가 실패했다.

### 무엇을 수정했는가
* export runner가 normal UPM resolution으로 실행되도록 `-noUpm`을 제거했다.
* export runner가 Unity lock file 3종을 먼저 확인하고, open-project 상태를 deterministic message로 알려주도록 preflight를 추가했다.
* export runner environment helper가 `PROGRAMDATA`와 `ALLUSERSPROFILE`도 보강하도록 확장했다.
* export runner가 `UnityPackageManager.exe`를 먼저 IPC mode로 띄우고 Unity batch launch에 `-upmIpcPath`를 전달하도록 자동화했다.
* raw zip helper가 `System.IO.Compression` + `System.IO.Compression.FileSystem` assembly를 모두 로드하도록 고쳤다.
* branch asset export workflow 문서에 `close Unity first, then export` rule을 명시했다.

### 왜 그렇게 판단했는가
* current goal은 branch asset maintenance를 안정적으로 반복 가능한 절차로 만드는 것이므로, misleading compile/crash log보다 deterministic preflight failure가 훨씬 안전하다.
* actual `.unitypackage`와 raw zip 생성은 editor-close 상태, valid Windows env, stable UPM IPC, usable archive assembly를 모두 만족해야 신뢰할 수 있으므로, 지금 필요한 fix는 compile 추측을 더하는 것보다 launch 조건과 automation shell contract를 명확히 하는 쪽이었다.
