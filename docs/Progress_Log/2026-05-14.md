## Topic 2. Boss replicated sound와 AoE visual ordering

### 오늘 반영한 작업
* `BasicAttackPattern`이 Attack1 ready window end에서 `DragonAttack1`을 재생하고, Host가 `BossReplicatedEffectKind.BasicAttackSound`를 remote client로 보내는 흐름을 정리했다.
* `ProjectileAttackPattern`과 `MultiplayerBossAuthorityBridge`의 projectile/AoE fireball replay SFX 호출을 boss effect replay 문서에 반영했다.
* `BossController.ResolveAuthoritativeAttackStartServerTick(...)`가 attack start tick을 한 번 resolve한 뒤 같은 공격 동안 고정하는 계약을 기록했다.
* `MultiplayerBossAuthorityBridge`의 AoE visual gate가 `TakeOff -> FlyForward -> FlyIdle -> Land` 순서를 앞으로만 진행시키고 duplicate/backward snapshot visual을 skip하는 구조를 문서화했다.

### 기술적 고려
#### 무엇을 발견했는가
* boss effect replay는 warning/projectile/AoE visual만이 아니라 impact/fireball/basic attack sound 같은 one-shot audio도 같은 display-only event layer에서 다뤄야 했다.
* AoE snapshots can arrive duplicated or slightly out of order, so the client needs a forward-only visual gate.

#### 무엇을 수정했는가
* 문서에는 `BasicAttackSound` effect kind, fireball replay SFX, AoE visual ordering gate, cached attack start tick을 함께 반영했다.

#### 왜 그렇게 판단했는가
* boss gameplay truth는 계속 Host-only로 유지하면서도, remote client가 보는 sound/VFX timing은 snapshot만으로 부족한 one-shot event를 별도로 받아야 자연스럽다.
