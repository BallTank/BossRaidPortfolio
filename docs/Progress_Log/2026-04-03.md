## 기술적 고려
### 무엇을 발견했는가
* `MultiplayerGameplaySceneCoordinator`의 boss target rebind는 authoritative player spawn 직후 1회만 실행되고 있었다.
* boss FSM의 detection/search/combat path는 `Controller.Target` 하나만 계속 읽으므로, 첫 target이 client이면 host가 더 가까워져도 감지 기준이 바뀌지 않았다.
* verify blocker는 `host도 boss에게 맞아야 HP test를 계속할 수 있다`였지, 완성형 aggro 우선순위가 아니었다.

### 무엇을 수정했는가
* `BossController`가 일정 간격으로 현재 씬의 살아있는 player 중 planar distance가 가장 짧은 대상을 다시 선택하게 했다.
* non-attack boss state들은 update 진입 시 이 retarget helper를 호출해, detection/combat/search decision이 latest closest player 기준으로 평가되게 했다.
* attack state 자체는 건드리지 않아 현재 공격 실행 계약은 유지했다.

### 왜 그렇게 판단했는가
* scene coordinator의 spawn-time one-shot rebind만으로는 runtime target 교체가 되지 않으므로, boss runtime 쪽에 작은 retarget 규칙이 필요했다.
* full aggro/contribution system을 지금 넣으면 scope가 커지므로, verify unblock에는 `closest live player` 규칙이 가장 작고 명확했다.
* attack 중 target까지 계속 흔들면 패턴 contract가 커질 수 있으므로, 이번 slice는 non-attack state refresh까지만 제한하는 편이 안전했다.
