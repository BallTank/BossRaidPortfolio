## 기술적 고려
### 무엇을 발견했는가
* `SoloPlayerAvatar`와 `MultiPlayerAvatar`는 NGO 기준에서 independent network prefab으로 다루기 어려웠고, Editor/Build 혼합 실행에서 prefab hash mismatch와 scene object collision을 만들었다.
* verify scene에 disabled prefab instance를 scene-placed `NetworkObject`로 남기면 runtime code가 scene load 이후 정리하기 전에 NGO가 먼저 registration을 시도한다.
* one shared network prefab으로 옮긴 뒤에도 presentation과 animator driver는 별도 binding 정리가 없으면 stale host visual / idle-only remote animation으로 남을 수 있다.

### 무엇을 수정했는가
* shared network prefab registration을 stable custom hash 기반으로 통일했다.
* verify scene player template를 network prefab instance 대신 plain marker object로 바꿨다.
* `PlayerController.RefreshVisualBindings()`와 `MultiplayerPlayerAvatar` visual role apply / `NetworkAnimator` retarget path를 추가했다.
* runtime config validation/editor guard와 temporary multiplayer diagnostic log를 넣어 failure stage를 더 빨리 구분할 수 있게 했다.

### 왜 그렇게 판단했는가
* prefab identity mismatch를 억지로 두 prefab 유지로 해결하려고 하면 Editor/Build compatibility와 scene registration risk가 다시 커진다.
* marker-based spawn template는 verify scene pose contract를 유지하면서 NGO scene object collision을 가장 작게 만든다.
* owner-based visual selection은 network truth(shared prefab)와 presentation truth(host/client look)를 분리하는 가장 안전한 intermediate step이다.
